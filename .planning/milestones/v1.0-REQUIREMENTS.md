# Requirements: 痛车设计生成 Agent

**Defined:** 2026-05-07
**Core Value:** 用户能用自然语言快速得到一套可预览、可迭代、可导出的高质量痛车设计方案。

## v1 Requirements

Requirements for the initial release. Each requirement maps to exactly one roadmap phase.

### Foundation

- [x] **FOUND-01**: Developer can run the frontend, API, worker, PostgreSQL, Redis, and MinIO locally from documented commands.
- [x] **FOUND-02**: Developer can validate the project with baseline lint, type-check, and test commands for frontend and backend.
- [x] **FOUND-03**: Frontend and backend share typed API contracts generated from FastAPI/Pydantic OpenAPI schemas.
- [x] **FOUND-04**: Operator can configure environment settings for storage, database, queue, AI providers, CORS, and runtime mode without code changes.

### Data And Jobs

- [x] **DATA-01**: User can create or resume a design workspace with conversation history.
- [x] **DATA-02**: System stores messages, structured design briefs, generation jobs, job events, design versions, artifacts, model runs, feedback, and exports durably in PostgreSQL/object storage.
- [x] **DATA-03**: User can upload reference images, logos, car photos, or inspiration assets with validation, thumbnails, and metadata.
- [x] **DATA-04**: User must record rights/source information for uploaded assets before those assets are used in generation or export.
- [x] **DATA-05**: User can see generation job status after refresh because job state is stored outside the browser and outside Redis-only task state.
- [x] **DATA-06**: System prevents duplicate expensive generation work by using idempotency keys for job creation and retryable stages.
- [x] **DATA-07**: System records estimated and actual provider cost fields for each generation job where provider data is available.

### Brief And Generation

- [x] **GEN-01**: User can describe a pain-car design in natural language, including vehicle/template, character/theme, style, palette, text, coverage, and references.
- [x] **GEN-02**: System converts user intent into a structured design brief that can be reviewed, edited, and reused.
- [x] **GEN-03**: User can select from one or more supported vehicle templates and supported views before generating.
- [x] **GEN-04**: System creates an image-generation prompt plan from the structured brief and stores the exact prompt, parameters, provider, model, and input assets.
- [x] **GEN-05**: User can submit a generation job and receive at least one 2D concept render through an asynchronous worker.
- [x] **GEN-06**: System stores generated outputs as immutable artifacts in object storage and links them to a design version.
- [x] **GEN-07**: User can see clear failure messages and retry eligible failed generation jobs without losing the original brief.

### Workbench UI

- [x] **UI-01**: User can use a GPT-style chat panel to submit design requests, view assistant/system feedback, and issue follow-up commands.
- [x] **UI-02**: User can inspect and edit structured design parameters in a dedicated parameter panel.
- [x] **UI-03**: User can upload and preview reference assets from the web workbench.
- [x] **UI-04**: User can view generation progress, queued/running/succeeded/failed states, and recent job events.
- [x] **UI-05**: User can view a selected 2D design in a preview workspace with zoom, pan, thumbnail history, and supported view switching.
- [x] **UI-06**: User can switch between generated variants and historical design versions without losing context.
- [x] **UI-07**: User can see unsupported future capabilities such as true 3D, print-ready export, or marketplace features as disabled, experimental, or explicitly deferred rather than silently available.

### Iteration And Export

- [x] **ITER-01**: User can regenerate from an existing design version while preserving the previous version.
- [x] **ITER-02**: User can request targeted changes to style, palette, text, composition emphasis, or coverage and receive a child design version.
- [x] **ITER-03**: User can compare parameter differences and lineage between a parent design version and a regenerated child version.
- [x] **ITER-04**: User can rate, approve, reject, or comment on a generated design version.
- [x] **ITER-05**: User can export a selected concept as PNG or JPG plus a metadata JSON manifest.
- [x] **ITER-06**: Export output clearly labels itself as concept preview unless production-ready validation is explicitly implemented later.

### Quality And Itasha Controls

- [x] **QUAL-01**: User can choose itasha-oriented presets or fields for character focus, supporting graphics, racing/JDM cues, typography intent, and color harmony.
- [x] **QUAL-02**: System renders exact text strings and uploaded logos through deterministic layers or overlays where possible instead of relying only on AI-rendered raster text.
- [x] **QUAL-03**: User can see lightweight warnings for low resolution, missing template data, unreadable text risk, face/text near risky vehicle zones, or uncertain rights metadata.
- [x] **QUAL-04**: User can use panel or safe-zone overlays for supported templates to understand basic vehicle-wrap constraints.
- [x] **QUAL-05**: System stores enough preview specification data to support later 3D preview without changing the core design/job APIs.

### Operations

- [x] **OPS-01**: Operator can inspect provider health, configured capabilities, and recent generation failures.
- [x] **OPS-02**: System classifies provider, validation, storage, queue, and unknown failures separately.
- [x] **OPS-03**: Operator can configure provider routing, fallback behavior, retry limits, timeouts, and rate limits.
- [x] **OPS-04**: System emits structured logs or error events for API, worker, queue, storage, and provider calls.
- [x] **OPS-05**: User can cancel eligible queued or running jobs and see the final canceled state.
- [x] **OPS-06**: System applies quota, credit, or rate-limit controls before expensive provider calls in non-local modes.

## v2 Requirements

Deferred to future releases. These are acknowledged but not part of the current v1 roadmap unless promoted explicitly.

### Production Handoff

- **PROD-01**: User can export layered source packages suitable for designer or wrap-shop review.
- **PROD-02**: User can run print preflight checks for scale, bleed, DPI, template layer separation, color notes, and text/logo vectorization.
- **PROD-03**: User can produce production-aware PDF/PSD/AI-style handoff packages with installer notes.

### 3D Preview

- **3D-01**: User can preview a design on a verified 3D vehicle model with camera presets.
- **3D-02**: System can map design textures through verified UV/material slots without stretching or mirroring errors.
- **3D-03**: User can preview material finish simulations such as matte, gloss, metallic, or holographic.

### Advanced Generation

- **ADV-01**: System can support richer local editing with masks, inpainting, ControlNet/IP-Adapter-style conditions, and layer-specific regeneration.
- **ADV-02**: System can evaluate multi-view consistency across side, front, rear, hood, and top views.
- **ADV-03**: System can promote stable pipeline stages into multi-agent orchestration when typed artifacts are proven.

### Business And Community

- **BIZ-01**: User can request quote/order/payment flows for wrap production.
- **BIZ-02**: User can share designs with collaborators, clients, or installers for approval.
- **BIZ-03**: User can publish or remix designs through a moderated community gallery.
- **BIZ-04**: User can select from a broad licensed vehicle-template and character-asset library.

## Out of Scope

Explicitly excluded from v1. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| One-click print-ready full wrap from any prompt | Vehicle wrap production requires verified templates, scale, bleed, color, layers, and installer proofing; v1 is concept preview. |
| Broad support for every vehicle model | Template coverage creates unbounded QA; v1 starts with one or a few supported templates. |
| Built-in copyrighted anime character library without licenses | It creates copyright/trademark risk and implies permission the product does not have. |
| LoRA training platform | Training adds dataset, GPU, safety, and quality complexity before the product loop is validated. |
| Full Photoshop/Illustrator clone | A complete design editor would consume the MVP; v1 needs targeted parameters, preview, iteration, and export. |
| Quote/order/payment/installer marketplace | Commercial workflow is valuable later but distracts from proving generation and preview quality. |
| Public social marketplace | Public sharing introduces moderation and IP workload before private design workflow is stable. |
| Production-grade 3D UV pipeline | Real 3D wrap preview depends on verified models, UVs, material slots, and preview/export consistency. |
