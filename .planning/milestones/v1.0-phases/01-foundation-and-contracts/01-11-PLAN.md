## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ignored `.env` file -> API process settings | Operator-provided local API config enters typed pydantic-settings. |
| ignored `.env` file -> worker process settings | Operator-provided local worker config enters typed pydantic-settings. |
| env examples -> source control | Example files must not contain real secrets while still documenting accepted keys. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11-01 | Information Disclosure | `.env.example` files | mitigate | Keep provider keys blank in local mode and retain `scripts/check-env-examples.mjs` checks for real-looking secrets. |
| T-01-11-02 | Tampering | API/worker settings | mitigate | Add tests that write temporary `.env` files and prove settings load documented keys from service cwd. |
| T-01-11-03 | Repudiation | provider env names | mitigate | Use one `AI_PROVIDER_*` key set across settings, examples, tests, guard, and docs. |
| T-01-11-04 | Elevation of Privilege | provider config | mitigate | Add no provider SDKs or calls; settings only parse/redact provider values. |
</threat_model>
