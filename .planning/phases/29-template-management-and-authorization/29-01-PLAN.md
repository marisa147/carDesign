# Phase 29 Plan: Template Management And Authorization

## Implementation Steps

1. API schema and validation service
   - Add `TemplatePackageValidationIssue` and `TemplatePackageValidationResponse` schemas.
   - Add a zip-safe package validator that reads `template.json`, `safe_zones.json`, `sections.json`, `forbidden_zones.json`, and referenced SVG/PNG assets.
   - Report missing files, invalid JSON, unsafe paths, unsupported image extensions, missing dimensions/export config, and missing authorization fields.

2. API route
   - Add `POST /templates/validate-package` accepting a multipart uploaded zip.
   - Return a structured validation report without registering the template.
   - Add tests for valid package, missing authorization, and path traversal.

3. Frontend API helper
   - Add `validateTemplatePackage(file)` helper with typed response.
   - Cover request method/body behavior in `templates.test.ts`.

4. Template management page
   - Add `/settings/templates` page.
   - List installed templates using existing catalog/detail APIs.
   - Show source class, supported views, authorization, version history, and import validation results.
   - Add page test with mocked fetch for listing, detail, and validation upload.

5. Contracts and planning state
   - Export OpenAPI and manually align contract types if generator remains blocked.
   - Mark TMPL-01..04 complete only after API/page verification passes or blocker is documented.
