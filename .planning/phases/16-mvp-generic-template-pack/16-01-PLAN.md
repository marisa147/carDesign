# Plan 16.01: Template Package Resource Model

## Goal

Introduce a package-backed template registry that can load five MVP internal-original template records with metadata, asset slot paths, source/license status, safe zones, and compatibility aliases.

## Tasks

1. Add core package constants for the five MVP template ids and template pack root.
2. Add a loader that reads each template's `template.json` and `safe_zones.json`.
3. Register the five MVP templates into `TEMPLATE_REGISTRY`.
4. Preserve `generic-side-coupe` as a legacy alias that resolves to the MVP coupe record.
5. Expose list/audit helpers for tests and later Phase 17 catalog API work.

## Acceptance

- `resolve_vehicle_template()` returns the selected MVP template id for all five MVP ids.
- `resolve_vehicle_template("generic-side-coupe")` returns the coupe-compatible template without breaking old callers.
- The selected brief payload carries correct label, source/license metadata, readiness, canvas, and safe zones.
