<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer shell -> root scripts | Local commands delegate into web, API, worker, contract, and infrastructure surfaces. |
| repository -> developer machine | Runtime pins and docs influence what tools contributors install and run. |
| git index -> future deployments | Ignore rules decide whether local secrets can accidentally enter source control. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01A | Information Disclosure | `.gitignore`, `.env*` handling | mitigate | Ignore real `.env`, `.env.local`, `.env.*.local`, service env files, and common secret material while allowing committed `.env.example` files per D-14. |
| T-01-05A | Information Disclosure / Tampering | README and `docs/development.md` | mitigate | Label Docker Compose and example credentials as local-development only; do not describe any production handoff path in Phase 1. |
| T-01-04A | Tampering / Repudiation | root contract scripts | mitigate | Reserve `contracts:generate` and `contracts:check` script names now so later plans can wire drift checks into `validate` without changing the command surface. |

No high severity threat is left unmitigated in this plan.
</threat_model>
