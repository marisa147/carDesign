# Phase 01 - UI Design Contract

> Visual and interaction contract for Phase 1 only. Generated by gsd-ui-researcher for the minimal runnable foundation shell.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui planned for `apps/web`; no `components.json` exists before Phase 1 scaffold |
| Preset | Official shadcn/ui Next.js setup, Tailwind CSS baseline, CSS variables enabled, neutral base color, radius capped at 8px |
| Component library | Radix primitives through shadcn/ui official registry only |
| Icon library | `lucide-react` for status, navigation, toolbar, and CTA icons |
| Font | System sans stack: `system-ui`, `-apple-system`, `Segoe UI`, `PingFang SC`, `Microsoft YaHei`, `sans-serif` |

Source: Phase 1 context D-20/D-21, project stack research, `UI.png` visual direction.

---

## Phase 1 Shell Scope

Phase 1 implements a minimal Next.js app shell that proves the frontend stack and API contract path. The first screen must feel like the future workbench without pretending that product workflows exist.

Required route layout:

| Area | Contract |
|------|----------|
| Root route `/` | App shell with top bar, compact left rail, and main foundation status region |
| Top bar | 56px height, brand text `痛车设计 Agent`, environment badge, and one primary CTA |
| Left rail | 280px desktop width; contains disabled workbench region labels and active `Foundation` item |
| Main region | Shows foundation cards for Web, API, Worker, Contracts, and Local Services readiness |
| Placeholder workbench regions | Conversation, Preview, History, Upload, Generation, Export, and 3D may appear only as disabled labels or muted empty panels |
| Footer/status strip | 32px desktop height; displays local mode, API base URL state, and contract generation status when available |

Explicitly deferred from Phase 1: full chat behavior, user message composer, parameter editing, asset upload, 2D preview controls, 3D preview, generation flow, variant history, feedback, export, product data tables, auth, marketplace, and production handoff.

## Visual Hierarchy

| Priority | Element | Contract |
|----------|---------|----------|
| 1 | Foundation status region | Primary visual anchor; first card row shows Web, API, Worker, Contracts, and Local Services readiness |
| 2 | `检查堆栈健康` CTA | Only filled accent button on the screen |
| 3 | Active `Foundation` rail item | Thin accent left border or underline, not a filled purple panel |
| 4 | Disabled future workbench labels | Muted supporting context; must not compete with the foundation status cards |

The eye should land on the foundation status cards first, then the health-check CTA. Placeholder workbench regions must stay visually quiet.

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Primary CTA | `检查堆栈健康` calls the typed API health client or a local mock state until the FastAPI endpoint exists |
| Loading | CTA enters disabled loading state with spinner icon and text `正在检查服务...` |
| Success | Foundation cards update to neutral `已连接` or `已生成` badges; do not add green-heavy success styling |
| Error | Surface one inline alert in the main region; keep the shell usable and show the recovery command/context |
| Disabled future controls | Disabled controls must use `aria-disabled="true"`, muted color, and tooltip/copy `后续阶段开放` |
| Keyboard | Tab order: top bar CTA, left rail items, main cards, footer links; focus ring uses accent color |
| Pointer targets | Desktop controls use 36px height; touch/mobile controls use at least 44px height |
| Responsive | Desktop uses rail plus main region; below 900px the rail becomes a horizontal segmented row; below 640px cards stack in one column |

The shell must not include a prompt input, upload button, generate button, export button, canvas controls, or live preview interactions in Phase 1.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, focus ring offset |
| sm | 8px | Compact control gaps, card inner group spacing |
| md | 16px | Default card padding, form/control spacing |
| lg | 24px | Main region padding, panel spacing |
| xl | 32px | Desktop layout gutters, shell section separation |
| 2xl | 48px | Empty-state vertical spacing on wide screens |
| 3xl | 64px | Maximum page-level spacing; avoid on compact workbench surfaces |

Exceptions: 1px borders and separators are allowed; desktop icon-only buttons may be 32px square; touch targets must be at least 44px square.

## Typography

Use exactly these four sizes and two weights in Phase 1.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 400 | 1.333 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.15 |

Typography rules:

| Rule | Contract |
|------|----------|
| Weights | Only 400 and 600 |
| Letter spacing | 0 for all text |
| Hero text | Not used in Phase 1; this is a workbench shell, not a landing page |
| Button text | 14px/600, single line on desktop, may wrap to two lines on narrow mobile only |
| Card headings | 14px/600 or 20px/600 depending on hierarchy; never display scale inside compact cards |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8FAFC` | App canvas, page background, low-emphasis empty space |
| Secondary (30%) | `#FFFFFF` | Cards, top bar, rail, status panels, disabled placeholder regions |
| Accent (10%) | `#6D5DF6` | Primary CTA, active rail item, active tab/segmented item, focus ring, thin progress indicator |
| Destructive | `#DC2626` | Reserved for destructive actions and critical error text; Phase 1 has no destructive actions |

Accent reserved for: `检查堆栈健康` primary CTA, active `Foundation` navigation state, active tab/segmented item, keyboard focus ring, and one thin loading/progress indicator. Do not use purple gradients, decorative blobs, decorative orbs, full-panel purple fills, or purple-tinted backgrounds across large surfaces.

Neutral support colors:

| Token | Value | Usage |
|-------|-------|-------|
| Text primary | `#111827` | Primary labels and headings |
| Text secondary | `#4B5563` | Body copy and metadata |
| Text muted | `#9CA3AF` | Disabled future-region labels |
| Border | `#E5E7EB` | Card, rail, and toolbar separators |
| Soft panel | `#F3F4F6` | Disabled placeholder surfaces and skeleton areas |

## Component Inventory

Phase 1 may use only these shadcn/ui components from the official registry:

| Component | Use |
|-----------|-----|
| `button` | Primary health check and secondary disabled shell actions |
| `badge` | Runtime mode, connected/unavailable, generated/stale contract state |
| `card` | Individual foundation readiness panels only |
| `separator` | Top bar, rail, and footer separation |
| `tabs` | Optional foundation/contract/log tabs if implemented as static shell navigation |

## Tailwind Baseline

| Area | Contract |
|------|----------|
| Styling mode | Tailwind utility-first styling with CSS variables generated by shadcn/ui |
| Radius | 8px max for cards, buttons, inputs, and badges |
| Shadows | Use no shadow by default; one subtle `shadow-sm` equivalent is allowed on the top bar or active card only |
| Borders | Prefer 1px neutral borders over shadows for structure |
| Gradients | Not allowed in Phase 1 app shell |
| Decorative imagery | Not allowed in Phase 1; `UI.png` informs layout density only |
| Dark mode | Not required in Phase 1; do not spend implementation time on a full dark theme |

## Accessibility Contract

| Area | Contract |
|------|----------|
| Contrast | Text and controls must meet WCAG AA contrast on light neutral surfaces |
| Focus | Every interactive element has visible `#6D5DF6` focus ring with 2px ring width |
| Disabled future regions | Use semantic disabled states or `aria-disabled`; include non-visual explanation through tooltip or accessible description |
| Landmark structure | Use `header`, `nav`, `main`, and `footer` landmarks |
| Motion | Loading spinner may rotate; no parallax, animated backgrounds, or decorative motion |
| Mobile | No horizontal scrolling at 320px width; cards stack and text wraps cleanly |
