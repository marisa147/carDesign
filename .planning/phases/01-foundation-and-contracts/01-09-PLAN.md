<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer root shell -> all project subsystems | `pnpm validate` invokes frontend, backend, worker, contract, env, and static smoke checks. |
| docs -> operator behavior | Final docs can cause unsafe assumptions if local defaults look production-ready. |
| generated artifacts -> validation result | Contract drift must be detected before the phase is considered complete. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01I | Information Disclosure | final docs and env validation | mitigate | `pnpm validate` includes `node scripts/check-env-examples.mjs`; docs instruct real secrets go only into ignored env files. |
| T-01-02I | Information Disclosure / Elevation | aggregate static checks | mitigate | `pnpm validate` includes frontend tests/static checks from plan `01-08` proving no backend internals or provider keys in browser code. |
| T-01-03I | Tampering / Information Disclosure | CORS config validation | mitigate | API tests and env guard are included in aggregate validation so wildcard CORS cannot silently pass. |
| T-01-04I | Tampering / Repudiation | contract drift | mitigate | `pnpm validate` includes `pnpm contracts:check` and fails when OpenAPI/client artifacts drift. |
| T-01-05I | Information Disclosure / Tampering | local infra docs | mitigate | Docs and README explicitly label Compose credentials and exposed ports as local-only and not production deployment guidance. |
</threat_model>
