<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/client -> API | Future frontend calls `/health`; API must expose only typed safe data. |
| environment -> API/worker process | Env vars configure DB, Redis, S3, CORS, runtime mode, and provider key entries. |
| worker -> Redis broker | Worker boot uses broker configuration without importing API routers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01B | Information Disclosure | API/worker settings | mitigate | Store provider keys as `SecretStr`, do not log secret values, and test that settings string output excludes raw secrets. |
| T-01-02B | Information Disclosure / Elevation | worker imports | mitigate | Worker imports only `caragent_worker` modules and Celery; tests scan for `caragent_api.routers` imports in worker source. |
| T-01-03B | Tampering / Information Disclosure | CORS middleware | mitigate | Parse `CORS_ORIGINS` into explicit origins; reject `"*"` when runtime mode is not `local` or when credentials are enabled. |
| T-01-04B | Tampering / Repudiation | OpenAPI export | mitigate | Provide deterministic `export_openapi.py` CLI so contracts can be regenerated and compared by plan `01-03`. |

No high severity threat is left unmitigated in this plan.
</threat_model>
