# Phase 28 Plan: GR86/BRZ Template Package Schema

## Scope

Extend the template registry and validator from side-only MVP templates to a first deep maintained vehicle package: `toyota_gr86_brz_v1`. This phase addresses TPLG-01 through TPLG-04.

## Requirements Addressed

- TPLG-01
- TPLG-02
- TPLG-03
- TPLG-04

## Implementation Steps

1. Extend the core template schema.
   - Add additive fields to `VehicleTemplateRecord`: `supported_views`, per-view asset metadata, sections, forbidden zones, dimensions, scale, export config, and authorization status.
   - Keep legacy side-only template records valid by defaulting `supported_views` to `[view]` and optional construction fields to empty/None.

2. Add the maintained GR86/BRZ template package.
   - Create `toyota_gr86_brz_v1` under the template pack resources.
   - Include distinct internally generated PNG assets for `side`, `front`, `rear`, and `top`.
   - Include `template.json`, `safe_zones.json`, `sections.json`, and `forbidden_zones.json` with real-unit dimensions and package metadata.

3. Update registry/resource lookup and API exposure.
   - Register `toyota_gr86_brz_v1` alongside the existing generic MVP templates.
   - Make catalog filtering by `view=front|rear|top` find templates whose `supported_views` include that view.
   - Expose construction metadata on template detail responses without breaking existing catalog fields.

4. Update validator.
   - Preserve MVP side-only validation behavior for existing generic templates.
   - Add deep package validation for required four views, metadata, sections, safe zones, forbidden zones, dimensions, scale, export config, and authorization status.
   - Ensure invalid/missing deep package fields produce clear errors.

5. Add focused tests and run validation.
   - Core tests for schema defaults and GR86/BRZ registry metadata.
   - API tests for catalog/detail/filter behavior.
   - Validator command/test covering the new deep package.

## Acceptance Criteria

- `toyota_gr86_brz_v1` is returned by template catalog APIs and can be selected as a maintained template.
- Template detail exposes `supported_views` containing `side`, `front`, `rear`, and `top`.
- Template detail exposes sections, forbidden zones, dimensions, scale, export config, and authorization status.
- Validator fails closed if required GR86/BRZ views or construction metadata are absent.
- Existing generic side-only templates still validate and remain catalog eligible.
